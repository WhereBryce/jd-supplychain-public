WHY ORDER-LEVEL

库存有货，不等于订单能被理想履约

一笔订单可能包含多个 SKU，它们分散在不同城市、不同仓网和不同履约节点。订单级判断的任务，是在这些约束下找到一个完整、可执行且结果稳定的方案。

01

单品有货，整单未必有货

每个 SKU 各自有库存，但没有一个节点能同时满足整笔订单。

02

能覆盖，不代表是本地

覆盖关系决定“能不能服务”，物理位置决定“是否本地、同区或跨区”。

03

少仓不一定优先

为了减少一个包裹而放弃本地已有库存，可能违背业务策略和库存治理目标。

04

成本不是唯一目标

完整满足、主赠体验、整单保护和本地承担通常先于成本比较。

FOUR COORDINATES

先把订单放进四个坐标系

同一个“仓”字可能指城市、配送中心、库房或仓网。只有先统一最小粒度，才能稳定判断同仓、跨仓和费用。

TO

履约 to

消费者城市经规则收敛后的应发货城市，是判断本地、同区和跨区的需求基准。

FROM

履约 from

实际出货的最小节点。分析时通常要细到“配送中心 + 库房”，而不是只看城市。

PLACE

物理城市与区域

描述节点真实所在地。覆盖能力不会改变一个履约 from 的物理位置。

NETWORK

仓网

不同仓型形成不同的服务网络、覆盖规则和成本结构，例如常规仓网与特殊仓网。

DETERMINISTIC SEQUENCE

履约是分层决策，不是一次性最低成本

先判断业务场景，再在允许的候选集合中比较。相同输入始终得到相同结果，才能复盘、审计和治理。

01

完整满足

候选库存合计必须满足全部 SKU 和数量，否则输出缺货，而不是给出半个方案。

02

识别订单类型

普通单、同品类订单、跨品类订单和主赠订单，对整单保护的要求不同。

03

保护适合的整单

主赠或同品类订单优先寻找合理范围内的单节点整单方案，降低主赠分离和无谓拆包。

04

最大化本地承担

整单方案不存在时，优先使用应发货城市已有库存，再为缺口寻找外部来源。

05

选择更优覆盖

原覆盖节点优先于兜底节点；区域兜底通常优先于更远的跨区寻源。

06

比较增量成本

只有前置业务条件相同时，才比较新增节点、配送异常和跨网成本。

07

减少节点并固定排序

成本相同时减少履约 from，并用稳定顺序打破最后的平局。

通用排序思想 完整满足 → 业务完整性 → 本地承担 → 覆盖层级 → 增量成本 → from 数量 → 稳定顺序

    RESULT LANGUAGE

    一个履约结果，需要四个维度共同描述

    地理

    本地 / 同区 / 跨区

    比较履约 from 的物理位置与履约 to。

    网络

    同网 / 跨网

    判断所用节点是否属于同一个服务网络。

    仓级

    同仓 / 跨仓

    看订单使用一个还是多个履约 from。

    包裹

    整单 / 拆单

    描述消费者收到一个还是多个履约子单。

    示例：“同区跨城 · 同网 · 跨仓 · 拆单”比单独写“代发”更精确，也更容易找到成本和库存问题的来源。

    UPCHARGE FRAMEWORK

    Upcharge 是偏离理想履约后的增量

    分析基准通常是“应发货城市由一个合适节点整单发出”。当订单引入更多节点、更远距离或不同网络时，才产生额外成本。

    总增量成本 新增节点生产 + 特殊网络配送 + 地理异常配送 + 跨网络调整

    具体费率、抵减、结算和责任归属属于版本化业务规则，不应与通用履约理论混为一谈。

    A

    确定基础 from

    每单先确定一个基准节点，它通常不承担“新增节点”生产成本。

    B

    识别新增 from

    每增加一个履约节点，通常意味着新增拣选、出库或包裹生产。

    C

    识别地理异常

    同区跨城、跨区和本地加异地拆单具有不同的运输结构。

    D

    处理跨网关系

    不同仓网组合可能产生额外成本，也可能与地理费用取高而非简单叠加。

    BUNDLE ORDERS

    绑赠增加的不是一个 SKU，而是一个完整性约束

    主品有货不代表整套机制可被理想履约。赠品库存放在哪里，会直接改变整单率、拆单率、跨区率和消费者体验。

    MODEL BOUNDARY

    把分析模型和真实生产路由分开

    模型可以回答
    • 在给定库存切片和覆盖规则下，订单可能如何分仓。
    • 哪些 SKU 或城市导致拆单、跨区和多节点履约。
    • 仓网或绑赠方案改变后，结构性成本如何变化。
    • 相同输入能否得到稳定、可复盘的结果。
    模型不能直接代表
    • 京东平台实时生产环境中的最终路由决策。
    • 考虑时效、线路、仓容和动态订单队列后的真实结果。
    • 最终物流账单、合同结算或费用责任归属。
    • 库存随多笔订单连续消耗的完整仿真。
    本页描述的是基于库存切片和配置规则构建的供应链分析框架，不代表京东官方实时路由算法，也不等同于最终物流账单或结算规则。
