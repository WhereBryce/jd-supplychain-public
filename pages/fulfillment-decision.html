LOCAL CONFIGURATION

数据与计费规则

配置影响范围：A修改参数后，只影响A当前浏览器；不会修改团队默认密文，也不会影响B或其他用户。
同仓定义：订单只使用1个履约from，即同一个“配送中心 + 库房名称”；使用2个及以上履约from为跨仓，同一配送中心下两个不同库房仍算跨仓。
履约from：宝洁直送明细中唯一“配送中心 + 库房名称”的数量；不是配送中心与库房的笛卡尔积。当前包含--个普通C仓、--个轻货仓、--个城市仓。

城市收敛映射

消费者城市 → 应发货城市

路由与 Upcharge 规则

总Upcharge = 出库费Upcharge + 配送费Upcharge
履约优先级同一级类目订单先找同区单仓整单；无解时回到应发货地库存优先拆单。跨一级类目订单直接优先使用应发货地库存，允许拆单。同区整单多仓原覆盖关系优先，其次总upcharge最低，最后按固定from顺序决胜。普通路径配送同区跨城0.8元按订单一次；每个不同跨区区域3元；跨网3元与地理配送取高、不叠加。特殊仓轻货仓和城市仓每个新增from收1元出库费Upcharge+2元配送费，逐from累加；城市仓仅服务本地城市。

DECISION FOUNDATION

逻辑基础

一句话

先按订单全部SKU（含赠品）的一级类目判断订单类型：同品类优先同区单仓整单，跨品类优先使用应发货地库存并允许拆单；再按覆盖、upcharge与固定from顺序完成确定性求解。

01

对象与库存口径

履约 to
消费者城市收敛后的应发货城市。
履约 from
唯一“配送中心 + 库房名称”，是同仓/跨仓与计费的最小粒度。
库存
使用所选日期24:00切片的可订购库存；大于0才可满足，负数按0。
订单关系
多笔订单独立判断，不跨订单连续扣减库存；单笔内部必须满足完整数量。
02

需求收敛与供给覆盖

  1. 需求侧：消费者城市本身是宝洁直送城市时保持本地；否则按城市映射收敛到应发货城市。
  2. 普通C仓：默认启用跨区域平行兜底；原覆盖关系优先，不足时网络内所有区域、城市和from可在全国互相代发。
  3. 轻货仓：原关系表覆盖城市优先；对应仓缺货时，其他轻货仓自动跨区代发全国。
  4. 城市仓：只覆盖物理所在城市。
03

履约求解优先级

1完整满足单笔订单
→
2同品类先找同区单仓整单
→
3无同区整单或跨品类时，优先应发货地库存并允许拆单
→
4原覆盖优先，再最小化upcharge
→
5按固定from顺序稳定决胜

订单类型按全部SKU（含赠品）的一级类目去重判断；一级类目缺失时保守按跨品类处理。同区整单多仓按“原覆盖 → 总upcharge → 固定from顺序”选择。

04

模式与拆单

地理层级本地同城 / 同区跨城 / 跨区
网络层级同网 / 跨网
仓级1个from为同仓；2个及以上为跨仓
拆单子单数=from数；额外拆单数=max(from数-1, 0)

模式占比按“地理层级 × 网络层级 × 仓级”组合统计；拆单状态与数量在结果明细独立展示。

05

Upcharge构成

普通C仓新增from出库费Upcharge 1.5元/from
轻货仓/城市仓新增from出库费Upcharge 1元 + 配送费2元/from
同区跨城配送存在即收0.8元，同区多个from合并一次
跨区配送每个不同跨区区域3元，同区域多个from合并
普通路径跨网3元，与普通地理配送取高、不叠加

总Upcharge = 出库费Upcharge + 特殊仓配送费 + max(普通地理配送费, 普通跨网配送费)。

06

绑赠机制模拟

城市权重w(c) = 主品在城市c近90日收货地商品件数 ÷ 全国件数
模式概率P(m) = Σ w(c) × I[城市c判定为模式m]
平均成本E(U) = Σ w(c) × 城市c的upcharge
  1. 指定一个地域分布基准主品；同一配送中心跨RDC重复件数只计一次。
  2. 每个应发货城市独立用完整机制SKU与数量求解，不跨城市扣减库存。
  3. 这里的“概率”是按主品商品件数地域分布加权的预计占比，不是随机库存概率，也不是订单数概率。
